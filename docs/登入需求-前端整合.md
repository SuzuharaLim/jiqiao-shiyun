# 任務 C：前端整合規格（串接真 API）

> 目標：把「機巧時運」前端從 localStorage 模擬登入改為串接 Node.js + Express + SQLite Session 後端。認證靠 **HttpOnly Cookie**，前端 **fetch 一律 `credentials:'include'`**，啟動時打 `GET /api/me` 還原登入態，`localStorage` 不再存任何敏感身分資料。

以下逐檔、逐元件、逐 API 給出「工程師可直接照做」的修改要點。假設後端與前端同源部署於 Cloud Run（`/api/*` 反向代理到 Express），故 fetch 用相對路徑 `/api/...`；若跨網域，另見 §0.3。

## 0. 全域基礎建設（先做，其他檔案都依賴它）

### 0.1 新增 `src/lib/api.js`（統一 fetch 封裝）

所有 API 呼叫都經過這裡，集中處理 `credentials:'include'`、JSON、CSRF、統一錯誤。

```js
// src/lib/api.js
const BASE = '/api'

// 後端登入/註冊等成功時回傳的 CSRF token 我們存在記憶體（非 localStorage）
let csrfToken = null
export const setCsrf = (t) => { csrfToken = t }
export const getCsrf = () => csrfToken

// 統一錯誤：後端請回傳 { error: { code, message } }
export class ApiError extends Error {
  constructor(code, message, status) {
    super(message); this.code = code; this.status = status
  }
}

async function request(path, { method = 'GET', body, headers } = {}) {
  const opts = {
    method,
    credentials: 'include',          // ★ 一定要有，Cookie 才會送出
    headers: { ...(headers || {}) },
  }
  if (body !== undefined) {
    opts.headers['Content-Type'] = 'application/json'
    opts.body = JSON.stringify(body)
  }
  // 非 GET 帶 CSRF（雙重提交 cookie 模式：header 需與 cookie 比對）
  if (method !== 'GET' && csrfToken) opts.headers['X-CSRF-Token'] = csrfToken

  let res
  try {
    res = await fetch(BASE + path, opts)
  } catch {
    throw new ApiError('NETWORK', '連線失敗，請檢查網路', 0)
  }

  // 204 無內容
  if (res.status === 204) return null

  let data = null
  try { data = await res.json() } catch { /* 可能無 body */ }

  if (!res.ok) {
    const code = data?.error?.code || 'UNKNOWN'
    const message = data?.error?.message || '發生錯誤，請稍後再試'
    throw new ApiError(code, message, res.status)
  }
  return data
}

export const api = {
  get: (p) => request(p),
  post: (p, body) => request(p, { method: 'POST', body }),
  patch: (p, body) => request(p, { method: 'PATCH', body }),
  del: (p, body) => request(p, { method: 'DELETE', body }),
}
```

**要點**
- `credentials:'include'` 不能漏，否則 Session Cookie 不會被瀏覽器附帶。
- CSRF token 存**記憶體變數**（非 localStorage、非 sessionStorage），reload 後會消失 → 但因為 `/api/me` 還原時後端會重發 CSRF token（見 §1），所以沒問題。
- 統一錯誤物件 `ApiError`，帶 `code`（給程式判斷）與 `message`（給人看，統一由後端給繁中訊息）。

### 0.2 統一錯誤訊息對照（前端 fallback）

後端訊息若已是繁中可直接用 `err.message`。前端保留一份 code → 訊息 fallback（防呆），放在 `src/lib/api.js` 或 `src/lib/authMessages.js`：

```js
export const AUTH_ERROR_MSG = {
  INVALID_CREDENTIALS: '帳號或密碼錯誤',      // 登入失敗統一訊息（防帳號列舉）
  EMAIL_TAKEN:         '此 Email 已被使用',   // 註冊時（見下方註記）
  RATE_LIMITED:        '嘗試次數過多，請稍後再試',
  EMAIL_NOT_VERIFIED:  '請先完成 Email 驗證',
  TOKEN_INVALID:       '連結無效或已過期，請重新申請',
  WEAK_PASSWORD:       '密碼強度不足（至少 8 碼，含大小寫與數字）',
  CSRF:                '安全驗證失敗，請重新整理後再試',
  NETWORK:             '連線失敗，請檢查網路',
  UNKNOWN:             '發生錯誤，請稍後再試',
}
```

> **帳號列舉權衡**：登入失敗一律回 `INVALID_CREDENTIALS`（不區分「查無此帳號」與「密碼錯」）。註冊/忘記密碼建議走「防列舉」流程：**忘記密碼**無論 Email 是否存在都回「若此信箱已註冊，將寄出重設信」；**註冊**若要避免列舉可改為「一律回成功並寄驗證信」，但這對 UX 較差，實務常見折衷是註冊時明說 `EMAIL_TAKEN`。此決策需與後端一致，前端照後端回傳顯示即可。

### 0.3 跨網域備註（若前後端不同源）

若最終前端（Vite build）與 API 不同源，需：
- 後端 CORS 設定 `origin: <前端網域>`、`credentials: true`。
- Cookie 需 `SameSite=None; Secure`（Strict 會擋跨站帶 Cookie）→ 與需求「SameSite=Strict」衝突。**建議同源部署**（Express 同時 serve 靜態檔），維持 `SameSite=Strict`，這也是本規格預設。

## 1. `src/store/nav.jsx`（登入態改由後端還原）

這是最核心的改動。現況：`user` 初值讀 localStorage、`useEffect` 寫回 localStorage。改為：啟動打 `GET /api/me`。

### 1.1 移除 localStorage 身分持久化

**刪除**第 21–29 行的 user 相關 `useState(讀 localStorage)` 與寫回 `localStorage` 的 `useEffect`。改為：

```js
import { api, setCsrf } from '../lib/api.js'

// user: null = 未登入；undefined = 尚在還原中（顯示啟動 Splash）
const [user, setUser] = useState(undefined)
const [authReady, setAuthReady] = useState(false)

// 啟動時還原登入態
useEffect(() => {
  let alive = true
  api.get('/me')
    .then(data => {
      if (!alive) return
      setUser(data.user)          // 後端回 { user: {...}, csrfToken }
      if (data.csrfToken) setCsrf(data.csrfToken)
    })
    .catch(() => { if (alive) setUser(null) })   // 401/網路錯 → 視為未登入
    .finally(() => { if (alive) setAuthReady(true) })
  return () => { alive = false }
}, [])
```

**保留** `theme`、`prefs`（非敏感 UI 偏好）的 localStorage —— 那些沒問題。只有 `jq-user` 這個敏感身分快取要拿掉。

### 1.2 `login` / `logout` / `updateProfile` 改為 async + API

```js
// 供 Auth.jsx 呼叫：實際 API 由 Auth 呼叫後，把回傳 user 塞進 store
const setSession = (u, csrf) => { setUser(u); if (csrf) setCsrf(csrf) }

const logout = async () => {
  try { await api.post('/auth/logout') } catch { /* 忽略，仍清前端態 */ }
  setUser(null); setCsrf(null); setStack([]); setTabRaw(0)
}

// 登出所有裝置
const logoutAll = async () => {
  try { await api.post('/auth/logout-all') } catch {}
  setUser(null); setCsrf(null); setStack([]); setTabRaw(0)
}

// 個人檔案：呼叫後端後再更新本地
const updateProfile = async (patch) => {
  const data = await api.patch('/me/profile', patch)  // 後端回更新後 user
  setUser(u => ({ ...u, ...data.user }))
}
```

> **重要相容性說明**：現在 `EditProfile.jsx` 的 `save()` 是同步呼叫 `updateProfile(patch)` 後直接 `pop()`。改成 async 後，`updateProfile` 會回 Promise。見 §7 對 EditProfile 的修改（要 await + try/catch + loading）。同理 `Settings.jsx` 的 `logout()` 現在同步呼叫，改 async 後要處理（見 §6）。

### 1.3 訪客模式（純前端，不打 API）

訪客不需要後端帳號，維持純前端旗標即可，但**不要**寫進 localStorage（避免與真登入態混淆）：

```js
const loginGuest = () => setUser({ name: '訪客', handle: 'guest', guest: true })
```

`App.jsx` 判斷 `!user` 時要注意 `undefined`（還原中）與 `null`（未登入）的差異，見 §2。

### 1.4 Context value 增補

在 `value` 物件加入並匯出：`authReady`、`setSession`、`logoutAll`、`loginGuest`。移除舊的直接 `login`（改由 Auth.jsx 走 API，成功後呼叫 `setSession`），或保留 `login` 名稱但改為 `setSession` 的別名以減少他檔改動。

**建議**：保留 `login` 名稱當作「已拿到後端 user 後寫入 store」的函式（= `setSession`），這樣其他檔案若有引用 `login` 不會壞。訪客另用 `loginGuest`。

```js
const value = {
  ...,
  user, authReady,
  login: setSession,      // (user, csrf) => 寫入 store
  loginGuest,
  logout, logoutAll, updateProfile,
  ...
}
```

## 4. 前端路由攔截：`/verify-email` 與 `/reset-password`（新增）

現在 App 沒有 URL router（全靠 tab/stack）。Email 連結會帶使用者到 `/verify-email?token=...`，需要在**未登入也能到達**的落地頁。做法：在 `App.jsx` 最外層（`device` 之前）依 `window.location.pathname` 攔截。

### 4.1 `App.jsx` 頂層路由判斷

```js
const path = window.location.pathname
if (path === '/verify-email')   return <VerifyEmail />
if (path === '/reset-password') return <ResetPassword />
// 否則走原本 SPA
```

### 4.3 新增 `src/screens/ResetPassword.jsx`（帶 token 的重設頁）

```jsx
import { useState } from 'react'
import { api } from '../lib/api.js'
import { AUTH_ERROR_MSG } from '../lib/api.js'
import { BRAND } from '../data/mock.js'

export default function ResetPassword() {
  const token = new URLSearchParams(window.location.search).get('token')
  const [pw, setPw] = useState('')
  const [pw2, setPw2] = useState('')
  const [showPw, setShowPw] = useState(false)
  const [loading, setLoading] = useState(false)
  const [err, setErr] = useState('')
  const [done, setDone] = useState(false)

  const submit = async (e) => {
    e.preventDefault(); setErr('')
    if (!token) { setErr('連結無效'); return }
    if (pw.length < 8) { setErr('密碼至少 8 碼，含大小寫與數字'); return }
    if (pw !== pw2) { setErr('兩次密碼不一致'); return }
    if (loading) return
    setLoading(true)
    try {
      await api.post('/auth/reset-password', { token, password: pw })
      setDone(true)   // 後端應同時撤銷所有既有 session
    } catch (e2) { setErr(AUTH_ERROR_MSG[e2.code] || e2.message) }
    finally { setLoading(false) }
  }

  if (done) return (
    <div className="auth body"><div className="auth-form" style={{ textAlign: 'center' }}>
      <p role="status">✅ 密碼已更新，請用新密碼登入。</p>
      <button className="auth-btn tap" onClick={() => window.location.href = '/'}>前往登入</button>
    </div></div>
  )

  return (
    <div className="auth body">
      <div className="auth-hero"><div className="auth-seal">印</div><div className="auth-title">{BRAND}</div>
        <div className="auth-sub">設定新密碼</div></div>
      <form className="auth-form" onSubmit={submit}>
        <div className="field">
          <label htmlFor="rp-pw">新密碼</label>
          <div className="pw-wrap">
            <input id="rp-pw" type={showPw ? 'text' : 'password'} value={pw}
                   onChange={e => setPw(e.target.value)}
                   autoComplete="new-password" placeholder="至少 8 碼" />
            <button type="button" className="pw-eye tap" aria-label={showPw ? '隱藏密碼' : '顯示密碼'}
                    aria-pressed={showPw} onClick={() => setShowPw(v => !v)}>{showPw ? '🙈' : '👁️'}</button>
          </div>
        </div>
        <div className="field">
          <label htmlFor="rp-pw2">確認新密碼</label>
          <input id="rp-pw2" type={showPw ? 'text' : 'password'} value={pw2}
                 onChange={e => setPw2(e.target.value)} autoComplete="new-password" />
        </div>
        {err && <div className="auth-err" role="alert">{err}</div>}
        <button type="submit" className="auth-btn tap" disabled={loading} aria-busy={loading}>
          {loading ? '更新中…' : '更新密碼'}
        </button>
      </form>
    </div>
  )
}
```

### 5.2 `Security.jsx` 要點

```jsx
import { useState } from 'react'
import { TopBar, SectionHead, ToolRow } from '../components/ui.jsx'
import { useNav } from '../store/nav.jsx'
import { api } from '../lib/api.js'

export default function Security() {
  const { logout, logoutAll, setToast } = useNav()
  const [busy, setBusy] = useState(false)
  // 改密碼欄位
  const [cur, setCur] = useState(''); const [nw, setNw] = useState(''); const [nw2, setNw2] = useState('')
  const [err, setErr] = useState('')

  const changePw = async () => {
    setErr('')
    if (nw.length < 8) { setErr('新密碼至少 8 碼'); return }
    if (nw !== nw2) { setErr('兩次新密碼不一致'); return }
    if (busy) return; setBusy(true)
    try {
      await api.post('/me/change-password', { currentPassword: cur, newPassword: nw })
      setToast('密碼已更新，其他裝置已登出')   // 後端應撤銷其他 session、保留本機
      setCur(''); setNw(''); setNw2('')
    } catch (e) { setErr(e.message) } finally { setBusy(false) }
  }

  const doLogoutAll = async () => {
    if (busy) return; setBusy(true)
    await logoutAll()   // §1.2：撤銷全部 session 並清前端 → App 回登入頁
  }

  const deleteAccount = async () => {
    if (!window.confirm('確定刪除帳號？此動作無法復原（GDPR：資料將被永久刪除）')) return
    if (busy) return; setBusy(true)
    try {
      await api.del('/me')          // 後端硬刪或匿名化，並清 session
      setToast('帳號已刪除')
      await logout()
    } catch (e) { setErr(e.message); setBusy(false) }
  }

  return (
    <>
      <TopBar title="帳號安全" onBack />
      <div className="body">
        <SectionHead title="變更密碼" />
        <div className="auth-form" style={{ maxWidth: 'none' }}>
          <div className="field"><label htmlFor="sec-cur">目前密碼</label>
            <input id="sec-cur" type="password" autoComplete="current-password"
                   value={cur} onChange={e => setCur(e.target.value)} /></div>
          <div className="field"><label htmlFor="sec-nw">新密碼</label>
            <input id="sec-nw" type="password" autoComplete="new-password"
                   value={nw} onChange={e => setNw(e.target.value)} /></div>
          <div className="field"><label htmlFor="sec-nw2">確認新密碼</label>
            <input id="sec-nw2" type="password" autoComplete="new-password"
                   value={nw2} onChange={e => setNw2(e.target.value)} /></div>
          {err && <div className="auth-err" role="alert">{err}</div>}
          <button className="auth-btn tap" disabled={busy} aria-busy={busy} onClick={changePw}>
            {busy ? '處理中…' : '更新密碼'}
          </button>
        </div>

        <SectionHead title="裝置與工作階段" />
        <ToolRow icon="🚪" bg="#ffedd5" title="登出所有裝置"
                 sub="撤銷所有已登入的工作階段" onClick={doLogoutAll} />
        {/* 可選：列出 active sessions（GET /api/me/sessions）逐一撤銷 */}

        <SectionHead title="危險操作" />
        <ToolRow icon="🗑️" bg="#fee2e2" title="刪除帳號"
                 sub="永久刪除帳號與個人資料（GDPR）" onClick={deleteAccount} />
      </div>
    </>
  )
}
```

**要點**
- 改密碼需帶 `currentPassword`（後端二次驗證）；成功後後端撤銷「其他」session（本機保留）。
- 刪除帳號用 `window.confirm` 二次確認（可換成自訂 Modal），對應 GDPR「被遺忘權」。
- 「登出所有裝置」「刪除帳號」成功後 `user` 變 `null`，App 自動回登入頁。
- 進階（可選）：`GET /api/me/sessions` 列出裝置（IP/UA/最後活動時間），逐一 `DELETE /api/me/sessions/:id` 撤銷。

## 9. 完整 API 對照表（前端呼叫）

| 功能 | Method | Path | Body | 成功回應 |
|---|---|---|---|---|
| 還原登入態 | GET | `/api/me` | — | `{ user, csrfToken }` / 401 |
| 註冊 | POST | `/api/auth/register` | `{name,email,password}` | `{ ok, devVerifyUrl? }` |
| 驗證 Email | POST | `/api/auth/verify-email` | `{token}` | `{ ok }` |
| 重寄驗證 | POST | `/api/auth/resend-verification` | `{email}` | `{ ok, devVerifyUrl? }` |
| 登入 | POST | `/api/auth/login` | `{email,password}` | `{ user, csrfToken }` |
| 登出 | POST | `/api/auth/logout` | — | 204 |
| 登出全部 | POST | `/api/auth/logout-all` | — | 204 |
| 忘記密碼 | POST | `/api/auth/forgot-password` | `{email}` | `{ ok, devResetUrl? }` |
| 重設密碼 | POST | `/api/auth/reset-password` | `{token,password}` | `{ ok }` |
| OAuth 起始 | GET(導頁) | `/api/auth/oauth/:provider` | — | 302 redirect |
| 改密碼 | POST | `/api/me/change-password` | `{currentPassword,newPassword}` | `{ ok }` |
| 更新檔案 | PATCH | `/api/me/profile` | `{name,handle,bio,avatar}` | `{ user }` |
| 刪除帳號 | DELETE | `/api/me` | — | 204 |
| (選)列裝置 | GET | `/api/me/sessions` | — | `{ sessions:[...] }` |

所有 non-GET 需帶 `X-CSRF-Token` header（`api.js` 自動處理）。
