## 架構

全端單一容器：Node 同時提供 `/api` 與打包好的前端。上雲後兩個服務搭配：

- **Cloud Run** — 跑程式（Express + React）；無狀態、按流量計費、閒置可歸零。
- **Cloud SQL (PostgreSQL)** — 存所有資料；獨立代管、**24 小時計費**、資料持久。

資料表開機自動建（`server/schema.sql`，`CREATE IF NOT EXISTS`）。本機無雲端時自動退回 SQLite。
> 觀念：資料庫不是建在 Cloud Run 上，而是旁邊獨立的 Cloud SQL，Cloud Run 連過去用。

## 更新伺服器（改完 code 後）

### 方式 1 · 手動重新部署
把新程式放進 Cloud Shell 的 `~/jiqiao`（見「重新打包上傳」），然後：
```bash
cd ~/jiqiao
gcloud run deploy jiqiao --source . --region=asia-east1
```
沿用先前環境變數／密碼，不用重設。純程式更新不需重跑整個 `deploy.sh`。

### 方式 2 · git push 自動部署（推薦長期）
把專案推到 GitHub → Cloud Run 主控台「設定持續部署」連上分支。之後更新 = `git commit` → `git push`，自動 build＋上線。

### 安全網：版本與一鍵回溯
每次部署都是一個 revision，更新壞了可立刻切回上一版（見下方指令）。

## 成本控制（重要）

**Cloud SQL 是 24 小時計費的。** `min-instances=0` 只讓 Cloud Run 運算閒置歸零，資料庫不論有沒有人用都持續計費。

```bash
gcloud sql instances stop  jiqiao-db     # 暫停（保留資料、停止 DB 計費）
gcloud sql instances start jiqiao-db     # 恢復

# 完全刪除（停止所有費用，會刪資料）
gcloud run  services  delete jiqiao   --region=asia-east1
gcloud sql  instances delete jiqiao-db
gcloud artifacts repositories delete cloud-run-source-deploy --location=asia-east1
```

## 常見問題／踩雷

| 症狀 | 原因 / 解法 |
| --- | --- |
| `/api/health` 回 `"db":"sqlite"` | 沒吃到 DB 環境變數；確認部署帶 `--add-cloudsql-instances` 與 `--set-env-vars INSTANCE_CONNECTION_NAME,DB_USER,DB_NAME`。 |
| 建置在 `npm ci` 失敗 | Dockerfile 勿用 `--omit=optional`（會拔掉 esbuild）；用完整 `npm ci` ＋建置階段裝 `python3 make g++`（已修正）。 |
| 紅字 `Gaia id not found` | 新帳號身分傳播中的無害警告，指令有跑完就忽略。 |
| 部署卡 `ERROR: Build failed` | 撈 build log 看真因（見下）。 |
| 首次部署 500 / 連不到 DB | 執行服務帳號缺 `cloudsql.client`／`secretAccessor`；`deploy.sh` 已自動授權。 |

```bash
# 撈最近一次建置失敗原因
gcloud builds log $(gcloud builds list --region=asia-east1 --limit=1 --format='value(id)') \
  --region=asia-east1 2>&1 | tail -60
```

## 資料庫備份與還原（P0：上線必開）

`deploy.sh` 已在建立/巡檢 Cloud SQL 時開啟**每日自動備份**（`--backup --backup-start-time=19:00` UTC＝台灣凌晨 3 點；gcloud 預設不開，勿移除旗標）。

```bash
# 確認備份已開啟
gcloud sql instances describe jiqiao-db --format='value(settings.backupConfiguration.enabled)'
# 既有實例補開（冪等）
gcloud sql instances patch jiqiao-db --backup-start-time=19:00

# 列出可用備份
gcloud sql backups list --instance=jiqiao-db
# 還原到某一備份（會覆蓋現有資料，先確認 BACKUP_ID）
gcloud sql backups restore BACKUP_ID --restore-instance=jiqiao-db
```

建議上線後**演練一次還原**（另建臨時實例 restore 驗證資料完整），並把結果記錄在此。
本機 SQLite（`server/data/auth.db`）僅為開發後備，重要測試資料請自行複製檔案備份。

## 部署到 Cloud Run（完整流程）

> 服務名稱預設 `jiqiao`、區域 `asia-east1`、Cloud SQL 實例 `jiqiao-db`。
> 腳本**冪等**，可重複執行；已存在的資源會略過或更新。

### 一次搞定（Cloud Shell）

```bash
# 1) 取得最新程式（已設定 gh auth login 後可直接 clone）
cd ~                     # ★ 必須先離開 ~/jiqiao，否則下一行會砍掉自己所在的目錄
rm -rf ~/jiqiao
git clone https://github.com/SuzuharaLim/jiqiao-shiyun.git ~/jiqiao
cd ~/jiqiao

# 2) 設定變數
export PROJECT_ID="你的專案ID"
export REGION="asia-east1"
export DB_PASS="你的資料庫密碼"          # 忘記可重設：export DB_PASS="$(openssl rand -hex 24)"
export GMAIL_USER="你的帳號@gmail.com"    # 寄信（選用但建議）
export GMAIL_APP_PASSWORD="16碼應用程式密碼"

# 3) 部署（約 10–15 分鐘）
bash deploy/deploy.sh
```

**之後每次更新**只要：
```bash
cd ~/jiqiao && git pull
bash deploy/deploy.sh
```
> 預設**不會**灌示範資料（只更新濾鏡/諺語/宜忌解釋等參考清單）。
> 真的需要示範資料時才加 `SEED_DEMO=1`。

### 腳本做了什麼（6 步）

| 步驟 | 內容 |
| --- | --- |
| 0 | 設定專案、啟用 API（run／sql／build／secret／artifact） |
| 1 | 建立 Cloud SQL PostgreSQL **並開啟每日自動備份**（既有實例會補開） |
| 2 | 把 DB 密碼與寄信金鑰存進 Secret Manager |
| 3 | 授權服務帳號（連 Cloud SQL、讀 Secret、跑 Cloud Build） |
| 4 | 透過 Cloud SQL Proxy 灌種子（`SEED_DEMO=0` 則只更新參考清單） |
| 5 | 從原始碼建置並部署到 Cloud Run |
| 6 | 回填 `APP_URL`、跑健康檢查 |

### 建立你自己的管理員（取代預設帳號）

預設的 `admin@jiqiao.local` 網域是假的，**收不到驗證信也無法用「忘記密碼」重設**，
而其預設密碼寫在文件裡＝等同公開後門。正式站請改用你自己的真實信箱：

1. 到 <https://chengqi.tw> 用你的信箱**註冊一般帳號**（會收到驗證信，記得點驗證）
2. 在 Cloud Shell 執行（透過 Proxy 連正式資料庫）：

```bash
cd ~/jiqiao && git pull
export DB_PASS="你的資料庫密碼"
./cloud-sql-proxy "$(gcloud sql instances describe jiqiao-db --format='value(connectionName)')" &
sleep 4
DATABASE_URL="postgresql://jiqiao_app:${DB_PASS}@127.0.0.1:5432/jiqiao"   npm run make:admin -- 你的信箱@gmail.com --disable-default
kill %1
```

`--disable-default` 會把 `admin@jiqiao.local` 降為一般使用者，並**作廢它所有登入 session**。
指令是冪等的，最後會列出目前所有管理者供你核對。

> 用「降級」而非刪除，是為了保留該帳號的歷史關聯，日後需要也能再升回來。

### AI 模型與成本

預設用 **`gpt-5.6-luna`**（2026-08-11 起；之前是 `gpt-5.4-nano`）。

| 模型 | 輸入 / 輸出（每 1M tokens） | 何時考慮 |
| --- | --- | --- |
| gpt-5.4-nano | $0.20 / $1.25 | 想把成本壓到最低。本顧問只做限定範圍的短問答，其實夠用 |
| gpt-5.4-mini | $0.75 / $4.50 | 覺得節氣文案語感不夠好時 |
| **gpt-5.6-luna** | **$1.00 / $6.00** | **預設**。理解力最強，成本也最高 |

> 價格為 2026-07 查詢值，會變動。最新見 <https://developers.openai.com/api/docs/pricing>

**成本估算**：一次對話約 600 token 輸入 + 300 輸出。
每天 100 次對話：

| 模型 | 每月約 |
| --- | --- |
| gpt-5.4-nano | NT$45 |
| **gpt-5.6-luna** | **NT$225**（約 5 倍） |

⚠️ 這個顧問有速率限制（每分鐘 15 次、以**使用者**為單位）與 200 字回覆上限，
所以成本是有天花板的；但換成 luna 之後同樣的用量會貴五倍，值得先看幾天的實際
用量再決定要不要留著。要改回去：`OPENAI_MODEL=gpt-5.4-nano` 重新部署即可。

**換模型不用改程式**：

```bash
gcloud run services update jiqiao --region=asia-east1   --update-env-vars=OPENAI_MODEL=gpt-5.4-mini
```

**查目前正式站用哪個**：

```bash
gcloud run services describe jiqiao --region=asia-east1   --format="value(spec.template.spec.containers[0].env)" | tr ',' '
' | grep -i model
```

沒有輸出＝沒設環境變數，用程式預設值（`server/index.js` 的 `OPENAI_MODEL`）。

> ⚠️ **Cloud Run 的環境變數是黏的**：一旦設過就會一直留在服務上，直到你明確改掉或
> 移除它。`deploy.sh` 用的是 `--update-env-vars`（只動列出的項目），所以
> **光是改程式裡的預設值再重新部署，並不會改掉已經釘在服務上的舊值**。
> 兩種做法：
>
> ```bash
> # 直接指定新的
> gcloud run services update jiqiao --region=asia-east1 --update-env-vars=OPENAI_MODEL=gpt-5.6-luna
> # 或移除它，讓程式預設值生效
> gcloud run services update jiqiao --region=asia-east1 --remove-env-vars=OPENAI_MODEL
> ```
>
> 改完進管理後台「系統狀態 → AI 測試」按一下，回應裡的 `model` 就是**實際生效**的那個
> （`/api/health` 只回 `ai: on/off`，看不到模型名）。

### 設定 AI 金鑰（OpenAI）

```bash
# 存進 Secret Manager（不留在指令記錄裡）
read -s -p "貼上 OpenAI 金鑰: " K; echo
printf '%s' "$K" | gcloud secrets create jiqiao-openai-key --data-file=- 2>/dev/null   || printf '%s' "$K" | gcloud secrets versions add jiqiao-openai-key --data-file=-
unset K

# 授權並掛上
PROJNUM="$(gcloud projects describe "$(gcloud config get-value project)" --format='value(projectNumber)')"
gcloud secrets add-iam-policy-binding jiqiao-openai-key   --member="serviceAccount:${PROJNUM}-compute@developer.gserviceaccount.com"   --role="roles/secretmanager.secretAccessor"
gcloud run services update jiqiao --region=asia-east1   --update-secrets=OPENAI_API_KEY=jiqiao-openai-key:latest

# 換過金鑰（走了上面的 versions add）就會多一個 Secret 版本，舊版本「停用」了也照收費 → 銷毀舊版本：
cd ~/jiqiao && bash deploy/cost-cleanup.sh   # 先看報告：DRY_RUN=1 bash deploy/cost-cleanup.sh
```

> ⚠️ **Secret 每多一個版本每月就多一筆費用**（停用的也算，只有銷毀才不收；2026-09 帳單 Secret Manager 452 TWD，
> 比 Cloud SQL 還貴，推測主要是舊版本累積的）。`cost-cleanup.sh` 每個 Secret 只留最新的 ENABLED 版本，其餘**銷毀（不可復原）**；
> 剛換的 24 小時內會多留前一版，隔天再跑一次（或下次跑 `deploy.sh`）才清掉。詳見 `docs/部署-CloudRun-PostgreSQL.md`「成本與關閉」。

確認：`curl -s https://chengqi.tw/api/health` 的 `ai` 應為 `on`。
未設金鑰時 AI 顧問會用內建示範回覆，不會壞掉。

> `deploy.sh` 也支援：部署前 `export OPENAI_API_KEY=sk-...` 就會自動建 Secret 並掛上。

### 掛回／新增其他金鑰（不影響既有設定）

```bash
# 查 Secret 名稱
gcloud secrets list --format="value(name)"

# 掛回 OpenAI 金鑰（--update- 只改指定項，不會動到其他）
gcloud run services update jiqiao --region=asia-east1   --update-secrets=OPENAI_API_KEY=你的secret名稱:latest

# 信件連結網址改用自訂網域
gcloud run services update jiqiao --region=asia-east1   --update-env-vars=APP_URL=https://chengqi.tw
```

> ⚠️ **永遠別用 `--set-env-vars` / `--set-secrets`**——那是「取代全部」，會把沒列出的設定清空。
> 要改單項一律用 `--update-env-vars` / `--update-secrets`。

只刪 `is_seed=1` 的示範作者及其連帶內容（貼文/作品/留言/讚由 FK CASCADE 清除）＋示範通知。
**真人帳號、真實上傳、參考清單都不受影響**，執行後會列出前後數量供核對。

### 改了參考清單（濾鏡／諺語／宜忌解釋）要重灌

這些存在 `ref_items`，**不會**隨程式部署自動更新，但 `deploy.sh` 每次都會更新它們，
所以照常 `bash deploy/deploy.sh` 即可。

> 資料庫「結構」（新欄位）會在伺服器啟動時自動遷移，不必手動處理。
