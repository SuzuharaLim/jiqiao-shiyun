## 架構

全端單一容器：Node 同時提供 `/api` 與打包好的前端。上雲後兩個服務搭配：

- **Cloud Run** — 跑程式（Express + React）；無狀態、按流量計費、閒置可歸零。
- **Cloud SQL (PostgreSQL)** — 存所有資料；獨立代管、**24 小時計費**、資料持久。

資料表開機自動建（`server/schema.sql`，`CREATE IF NOT EXISTS`）。本機無雲端時自動退回 SQLite。
> 觀念：資料庫不是建在 Cloud Run 上，而是旁邊獨立的 Cloud SQL，Cloud Run 連過去用。

## 更新伺服器（改完 code 後）

### 方式 1 · 手動重新部署
把新程式放進 Cloud Shell 的 `~/jiqiao`（見「重新打包上傳」），然後：
```bash
cd ~/jiqiao
gcloud run deploy jiqiao --source . --region=asia-east1
```
沿用先前環境變數／密碼，不用重設。純程式更新不需重跑整個 `deploy.sh`。

### 方式 2 · git push 自動部署（推薦長期）
把專案推到 GitHub → Cloud Run 主控台「設定持續部署」連上分支。之後更新 = `git commit` → `git push`，自動 build＋上線。

### 安全網：版本與一鍵回溯
每次部署都是一個 revision，更新壞了可立刻切回上一版（見下方指令）。

## 成本控制（重要）

**Cloud SQL 是 24 小時計費的。** `min-instances=0` 只讓 Cloud Run 運算閒置歸零，資料庫不論有沒有人用都持續計費。

```bash
gcloud sql instances stop  jiqiao-db     # 暫停（保留資料、停止 DB 計費）
gcloud sql instances start jiqiao-db     # 恢復

# 完全刪除（停止所有費用，會刪資料）
gcloud run  services  delete jiqiao   --region=asia-east1
gcloud sql  instances delete jiqiao-db
gcloud artifacts repositories delete cloud-run-source-deploy --location=asia-east1
```

## 設定金鑰／整合

### 接你的 GPT / OpenAI
金鑰只放後端（Secret Manager），前端拿不到。未設金鑰時 App 自動用內建示範腳本。
```bash
printf "%s" "sk-你的金鑰" | gcloud secrets create openai-key --data-file=-
PROJNUM="$(gcloud projects describe project-1f5dade0-75d4-4744-b04 --format='value(projectNumber)')"
gcloud secrets add-iam-policy-binding openai-key \
  --member="serviceAccount:${PROJNUM}-compute@developer.gserviceaccount.com" \
  --role="roles/secretmanager.secretAccessor"
gcloud run services update jiqiao --region=asia-east1 \
  --update-env-vars="OPENAI_MODEL=gpt-4o-mini" \
  --update-secrets="OPENAI_API_KEY=openai-key:latest"
```
驗證：`/api/health` 顯示 `"ai":"on"`。換 Azure/相容服務另設 `OPENAI_BASE_URL`。**勿把金鑰寫進前端或 commit 進版控。**

### 金流（讓使用者付款）

## 常見問題／踩雷

| 症狀 | 原因 / 解法 |
| --- | --- |
| `/api/health` 回 `"db":"sqlite"` | 沒吃到 DB 環境變數；確認部署帶 `--add-cloudsql-instances` 與 `--set-env-vars INSTANCE_CONNECTION_NAME,DB_USER,DB_NAME`。 |
| 建置在 `npm ci` 失敗 | Dockerfile 勿用 `--omit=optional`（會拔掉 esbuild）；用完整 `npm ci` ＋建置階段裝 `python3 make g++`（已修正）。 |
| 紅字 `Gaia id not found` | 新帳號身分傳播中的無害警告，指令有跑完就忽略。 |
| 部署卡 `ERROR: Build failed` | 撈 build log 看真因（見下）。 |
| 首次部署 500 / 連不到 DB | 執行服務帳號缺 `cloudsql.client`／`secretAccessor`；`deploy.sh` 已自動授權。 |

```bash
# 撈最近一次建置失敗原因
gcloud builds log $(gcloud builds list --region=asia-east1 --limit=1 --format='value(id)') \
  --region=asia-east1 2>&1 | tail -60
```

## 資料庫備份與還原（P0：上線必開）

`deploy.sh` 已在建立/巡檢 Cloud SQL 時開啟**每日自動備份**（`--backup --backup-start-time=19:00` UTC＝台灣凌晨 3 點；gcloud 預設不開，勿移除旗標）。

```bash
# 確認備份已開啟
gcloud sql instances describe jiqiao-db --format='value(settings.backupConfiguration.enabled)'
# 既有實例補開（冪等）
gcloud sql instances patch jiqiao-db --backup-start-time=19:00

# 列出可用備份
gcloud sql backups list --instance=jiqiao-db
# 還原到某一備份（會覆蓋現有資料，先確認 BACKUP_ID）
gcloud sql backups restore BACKUP_ID --restore-instance=jiqiao-db
```

建議上線後**演練一次還原**（另建臨時實例 restore 驗證資料完整），並把結果記錄在此。
本機 SQLite（`server/data/auth.db`）僅為開發後備，重要測試資料請自行複製檔案備份。
