## 1. 本機開發

```powershell
npm install            # 第一次先跑
npm run dev            # 前端開發伺服器（5173，改檔即時更新）
npm run dev:server     # 後端（8080，改檔自動重啟）
npm run build          # 打包前端到 dist/
npm run server         # 正式模式：一個 node 同時服務前端與 API（8080）
```

> ⚠️ 要測**登入相關**功能，`dev` 和 `dev:server` **兩個都要開**。
> 只想快速看畫面：`npm run build` 後跑 `npm run server`，開 <http://localhost:8080> 即可。

本機測試帳號（**僅本機有效**，正式站不是這組）：
```
newuser@example.com  / secret12345      一般使用者
admin@jiqiao.local   / admin12345       管理者
```

## 2. 資料庫（本機）

```powershell
npm run seed                  # 更新參考清單（濾鏡/諺語/宜忌解釋…），不灌示範資料
$env:SEED_DEMO="1"; npm run seed    # 連示範作者/貼文/作品一起灌（做展示用）
npm run purge:demo            # 清除示範資料，只留真人上傳
npm run make:admin -- you@gmail.com            # 把已註冊帳號升為管理者
npm run make:admin -- you@gmail.com --disable-default   # 同時把預設 admin 降級
```

改了**資料表結構**（加欄位）時，本機要砍舊資料庫重建：
```powershell
Remove-Item server\data\auth.db* -Force
npm run seed
```
> 正式站（Cloud SQL）不用——啟動時會自動遷移。

## 3.4 在手機上實測 AR（**不必部署**）

`/AR` 要開相機，而 `getUserMedia` **只在安全內容下可用**（HTTPS 或 localhost）。
所以能不能在手機上測，取決於手機看到的網址是什麼：

| 手機看到的網址 | 相機 | 適用 |
| --- | --- | --- |
| `http://localhost:5173`（USB 埠轉發） | ✅ 可用 | Android + Chrome |
| `http://192.168.x.x:5173`（區網 IP） | ❌ **一定被擋** | 只能測不用相機的頁面 |
| `https://chengqi.tw` | ✅ 可用 | 需先部署 |

### Android：USB 埠轉發（零安裝，相機可用）

1. 手機開「開發人員選項 → USB 偵錯」，用線接上電腦
2. 電腦這邊 `npm run dev`（照舊，只綁 localhost 就好）
3. 電腦的 Chrome 開 `chrome://inspect` → 左側 **Port forwarding** →
   勾 Enable，加一列 `5173` → `localhost:5173`
4. **手機**的 Chrome 開 `http://localhost:5173/AR`

⚠️ 關鍵在第 4 步的網址真的是 `localhost`——手機把它當成本機來源，
所以是安全內容，相機才開得起來。**這一步不能改成打電腦的 IP。**

### 不用相機的部分：區網就夠（含 iPhone）

```powershell
npm run dev:lan
```

Vite 會印出 `Network: http://192.168.x.x:5173/`，手機直接開。
`/ar/card/2027-xiaohan` 完全不用相機——海報、六個熱區、3D 白菜、小挑戰、
徽章、分享圖卡都能測，也能用「放大給另一台裝置掃描」。
⚠️ 但 `/AR` 在這個網址下**開不了相機**，症狀是「相機打不開」不是「掃不到」——
   別把它誤判成追蹤的問題。

### iPhone 要用相機：只能部署

Safari 沒有等同 Chrome 埠轉發的機制。要嘛部署（見 §4.0），
要嘛自備 HTTPS 通道——後者會把畫面送出去，測 AR 不值得。

## 3.5 AR 卡片（本機）

```powershell
npm run card:install -- 設計稿.png
```

加收邊（白留白邊＋深色實框）→ 在四種桌面亮度上驗證逐角誤差 → **驗證過了才**
裝進 `public/ar/targets/`（檔名由 `src/data/arCards.js` 決定）→ 另存一份
`設計稿-付印.png`。**付印稿與登錄目標是同一個檔案複製出來的。**

只想看收邊效果、還不想安裝：`npm run card:frame -- 設計稿.png`

> **⚠️ `public/ar/targets/` 是空的時候，`/AR` 完全掃不到任何東西**——不是效果差，
> 是沒有登錄目標可比對，四邊形照樣偵測得到但認不出是哪一張。症狀與「沒對準／
> 光線不夠」一模一樣，`/AR` 現在會顯示橫幅講明原因。
>
> **⚠️ 只吃 PNG**（自寫的解碼器不支援 JPEG／interlaced），且**不可用 JPG**——
> 壓縮雜訊會讓邊界對比變差。
>
> 裝好之後記得到 `/ar/card/2027-xiaohan` 開「熱區校對」重量六個 rect：
> 加收邊會讓版面內縮約 3.8%，原本的座標會整體偏掉。

## 4. 部署（Cloud Shell）

### 4.0 只改了程式碼 → 用這條（約 3–5 分鐘）

```bash
cd ~/jiqiao && git pull && gcloud run deploy jiqiao --source . --region=asia-east1
```

不必 `DB_PASS`、不動 Cloud SQL、不重跑種子，環境變數與 Secret 都保持原狀
（Cloud Run 的 env vars 是掛在服務上的，重新部署不會清掉）。
完整的 `deploy/deploy.sh` 只有在**動到基礎設施**（第一次建、換資料庫密碼、
加新的環境變數／Secret）時才需要。

**部署完一定要確認真的上線了**——一個網址就夠：

```
https://chengqi.tw/ar/targets/2027-xiaohan.png
```

出現卡面圖＝新版已上線；**404 或跳出網站首頁＝還是舊版**。

> ⚠️ **不要用 `/api/health` 判斷有沒有部署成功**：它只證明服務活著，
> 不含任何版本資訊——舊版一樣會回 `{"ok":true}`。
> ⚠️ 也不要用 `/llms.txt`：那個檔案是**刻意撤回**的（證實無效的三項之一），
> 它 404 是正確的，拿它推論會得到「部署非常舊」的錯誤結論。
>
> ⚠️ **「push 到 main 就會自動上線」不可當成事實**：2026-08-09 實測，
> 目標圖 commit 推上去一小時後正式站仍回 404，而本機 `dist/` 有那個檔、
> `git status` 也沒有未推的東西。push 之後請照上面那個網址確認一次。

### 4.1 完整部署（動到基礎設施時）

```bash
cd ~/jiqiao && git pull

export PROJECT_ID="project-1f5dade0-75d4-4744-b04"
export REGION="asia-east1"
export DB_PASS="你的資料庫密碼"

bash deploy/deploy.sh
```

約 10–15 分鐘，問 `(Y/n)` 按 `y`。

**可選環境變數**（設了才會更新，沒設的保持原狀不會被清掉）：
```bash
export GMAIL_USER="..." GMAIL_APP_PASSWORD="..."   # 寄信
export OPENAI_API_KEY="sk-..."                      # AI 顧問
export OPENAI_MODEL="gpt-5.4-nano"                  # 換模型
export SEED_DEMO=1                                  # 連示範資料一起灌（正式站別用）
export APP_URL="https://chengqi.tw"                 # 信件連結網址（預設自動抓自訂網域）
```

**忘記 DB_PASS**：直接設新的，腳本會同步更新資料庫與 Secret，不影響資料。
```bash
export DB_PASS="$(openssl rand -hex 24)"
```

**金鑰不留在指令記錄裡**：
```bash
read -s -p "密碼: " DB_PASS; echo; export DB_PASS
```

## 6. 正式站維運（Cloud Shell）

### 看記錄
```bash
gcloud run services logs read jiqiao --region=asia-east1 --limit=50
gcloud run services logs read jiqiao --region=asia-east1 --limit=50 | grep mail   # 只看寄信
```

### 改設定（`--update-` 只改指定項，不會清掉其他）
```bash
gcloud run services update jiqiao --region=asia-east1 \
  --update-env-vars=OPENAI_MODEL=gpt-5.4-nano

gcloud run services update jiqiao --region=asia-east1 \
  --update-secrets=OPENAI_API_KEY=jiqiao-openai-key:latest
```

> ⚠️ **絕對別用 `--set-env-vars` / `--set-secrets`**——那是「取代全部」，會把沒列出的設定清空。

### 查目前設定
```bash
gcloud run services describe jiqiao --region=asia-east1 \
  --format="value(spec.template.spec.containers[0].env)" | tr ',' '\n'
```

### 新增金鑰
```bash
read -s -p "貼上金鑰: " K; echo
printf '%s' "$K" | gcloud secrets create 金鑰名稱 --data-file=- 2>/dev/null \
  || printf '%s' "$K" | gcloud secrets versions add 金鑰名稱 --data-file=-
unset K

PROJNUM="$(gcloud projects describe "$(gcloud config get-value project)" --format='value(projectNumber)')"
gcloud secrets add-iam-policy-binding 金鑰名稱 \
  --member="serviceAccount:${PROJNUM}-compute@developer.gserviceaccount.com" \
  --role="roles/secretmanager.secretAccessor"
```

## 7. 正式站資料庫（Cloud Shell）

先開 Proxy 才能連（每次都要）：
```bash
cd ~/jiqiao
export DB_PASS="你的資料庫密碼"
./cloud-sql-proxy "$(gcloud sql instances describe jiqiao-db --format='value(connectionName)')" &
sleep 4
export DATABASE_URL="postgresql://jiqiao_app:${DB_PASS}@127.0.0.1:5432/jiqiao"
```

然後就能跑：
```bash
npm run purge:demo                                      # 清除示範資料
npm run make:admin -- you@gmail.com --disable-default   # 設定管理員
npm run seed                                            # 更新參考清單
```

用完關掉 Proxy：
```bash
kill %1
```

### 備份與還原
```bash
gcloud sql backups list --instance=jiqiao-db                    # 列出備份
gcloud sql backups restore 備份ID --restore-instance=jiqiao-db  # 還原（會覆蓋現有資料！）
gcloud sql instances describe jiqiao-db \
  --format='value(settings.backupConfiguration.enabled)'        # 確認自動備份已開
```

### 省錢暫停
```bash
gcloud sql instances stop jiqiao-db     # Cloud SQL 是 24h 計費的大宗
gcloud sql instances start jiqiao-db    # 要用時再開
```

## 10. 常見狀況

| 症狀 | 處理 |
| --- | --- |
| `npm error ENOENT ... package.json` | 不在專案資料夾，先 `cd` 過去 |
| `Unable to read current working directory` | 你在被刪掉的資料夾裡，`cd ~` 即可 |
| `請先 export PROJECT_ID` | Cloud Shell 重開後環境變數沒了，重設一次 |
| `REGION 的值不像區域名稱` | 變數被蓋掉，`export REGION="asia-east1"` |
| 部署後 `ai` 變 `off` | 舊版腳本問題，已修；用 §6 的 `--update-secrets` 掛回 |
| 正式站又出現示範作者 | 跑 `npm run purge:demo`（seed 預設已不灌，不會再倒回） |
| 改了 CMS 內容沒變 | 前端有快取，強制重新整理 `Ctrl+Shift+R` |
| 相機黑畫面 / 切鏡頭失效 | 已修（2026-07），確認正式站已部署最新版 |
