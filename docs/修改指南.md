# 修改指南（改東西前先查這份）

> **用法**：想改任何東西，先在這份文件用 `Ctrl+F` 搜你想做的事（例如「改價格」「加畫面」「改宜忌」），
> 它會告訴你 **①改哪個檔案 ②改哪一段/函式 ③會踩到的雷**。找到後再去該檔案修改。
> 這份是「地圖」，不是細節文件；深入原理見 `CLAUDE.md` 與各 `docs/*`。
> 最後更新：2026-07。**改動架構後請一併更新這份。**

---

## 0. 最重要的心智模型（先懂這三件事）

1. **內容 = 資料庫，不是程式碼。** 貼文／作品／留言／諺語／生肖／工具清單／濾鏡…全部存在資料庫（`ref_items` 表或各內容表）。
   想改「顯示的內容文字」→ **改資料庫，不改前端**（見 §2）。前端只是把 DB 資料畫出來。
2. **畫面 = `src/screens/*.jsx` 一個檔一個畫面。** 想改某頁的版面/文字/按鈕行為 → 找對應的畫面檔（見 §1 對照表）。
3. **樣式 = `src/styles.css` 用 token 驅動。** 想換顏色/字體/間距 → 改 CSS 變數（token），不用逐頁改（見 §3）。

> 一句話流程：**內容改 DB → 版面改畫面檔 → 配色改 token → 邏輯改後端 API。**

## 2. 我想改「顯示的內容資料」（文字、清單、價格…）

**內容都在資料庫。有兩種方式改：**

### 方式 A（推薦，免改碼）：用管理後台改
1. 用管理者帳號登入（`admin@jiqiao.local` / `admin12345（僅本機；正式站密碼由 ADMIN_PASSWORD 指定或隨機產生）`）。
2. 進「設定 → 管理後台」→ 內容 CMS，直接編輯（改的是 `ref_items` 的 JSON）。
3. 存檔即生效，不用重新部署。

### 方式 B：改種子檔再重灌（會改到「預設內容」）
種子內容在 `src/data/mock.js`。改完後：
```
npm run seed        # 把 mock.js 灌進資料庫（可重入）
```
> ⚠️ **本機改了欄位結構**要先砍舊 SQLite：刪 `server/data/auth.db*` 再 `npm run seed`
> （`schema.sql` 是 `CREATE IF NOT EXISTS`，不會自動補欄位）。正式 Cloud SQL 無此問題。

### 各種內容 → 存在哪個 `ref_items` kind
在 `src/data/mock.js` 找對應變數，seed 後變成 `GET /api/content/<kind>`：

| 內容 | kind | 前端讀取處 |
| --- | --- | --- |
| 台灣諺語 | `proverbs` | `InfoScreens.jsx` |
| 神佛誕辰 | `deities` | `Deities.jsx` |
| 特色慶典 | `festivals` | `InfoScreens.jsx` |
| 賞花景點 | `flowers` | `InfoScreens.jsx` |
| 當季食材 | `ingredients` | `InfoScreens.jsx` |
| 生肖運勢 | `zodiacs` | `Zodiac.jsx` / `Matchmaking.jsx` |
| 24 節氣專欄 | `solarTerms` | `InfoScreens.jsx` |
| 節氣挑戰 | `challenges` | `Challenges.jsx` |
| 命理工具清單 | `fortuneTools` | `Almanac.jsx` |
| 節氣文化工具清單 | `cultureTools` | `Almanac.jsx` |
| 排行榜 | `leaderboard` | `Leaderboard.jsx` |
| 探索篩選 chips | `exploreChips` | `Explore.jsx` |
| 月曆詩詞池 | `poemPool` | `CalendarPreview.jsx` |
| 宜/忌詞彙白話解釋 | `almanacTerms` | 曆頁三處（點詞顯示） |

> 但 `GET /api/content/:kind` 會**攤平**成字串陣列 → 前端直接當字串陣列用，別再取 `[0].chips`。

### 貼文/作品/留言等「使用者內容」
這些不在 `ref_items`，而在各自的表（`posts`/`works`/`comments`/`images`…），由使用者上傳或 `seed.js` 灌入示範。
**前端嚴格只吃 DB，載入前顯示空狀態，不再回退 mock。** 想改示範資料 → 改 `mock.js` 的 `posts`/`works` 再 `npm run seed`。

### 圖片（使用者上傳的真實照片）
- 上傳鏈：NewPost「上傳照片」→ 前端 canvas 壓縮（≤1600px JPEG）→ `POST /api/images` → 存 `images` 表 → `GET /api/images/:id` 供圖。
- 顯示：各畫面用 `PhotoImg`（`src/components/ui.jsx`）——有 `image` 顯照片、沒有回退 emoji 佔位。
- 想改壓縮尺寸/畫質 → `NewPost.jsx` 的 `compressImage`；想改大小/格式限制 → `server/index.js` 的 `/api/images`。

### 清除測試（Demo）資料 → 只留使用者上傳
1. 管理後台（admin 登入）→「上線清理」，或指令 `npm run purge:demo`（會列出清除前後數量）。
2. **seed 預設不灌示範資料**（`SEED_DEMO` 需明確設成 `1` 才會灌），所以部署不會把測試資料塞回來。
3. 排行榜不用清——已改成依真實作品讚數即時計算（`GET /api/leaderboard`）。

### 宜／忌 詞彙的白話解釋
- 文案在 `ref_items` 的 `almanacTerms`（可用管理後台 CMS 改），也可改 `mock.js` 的 `almanacTerms` 再 seed。
- **新增詞彙時 `term` 必須與 `almanac.js` 的 `YI_POOL`／`JI_POOL` 用字完全一致**，否則點了查不到。
- 元件在 `src/components/ui.jsx`：`useGlossary()` + `<GlossTerm>` + `<GlossPanel>`；
  三個畫面用它（`Feed.jsx`／`Almanac.jsx`／`AlmanacDay.jsx`）。查不到解釋的詞會自動退化成純文字。
- 諺語解釋來自 `proverbs` 的 `mean` 欄位，由 `dayFor()` 回傳 `proverbMean`。

### 相機（拍攝／版面／建立限動）
- 檔案：`src/screens/Camera.jsx`。三種模式在同一支：`capture`／`layout`／`create`。
- **限動貼紙的內容**（票選問題與選項、問答標題與提示、倒數標題與結束時間）
  都在 `CreateStory` 的 `poll` / `qa` / `cd` state，使用者可即時編輯，貼紙同步預覽。
  倒數只在選中時才跑 `setInterval`（不浪費效能），過期顯示「時間到 🎉」。
- ⚠️ **相機生命週期只能有「一個」地方管**：`Camera.jsx` 的那支 effect
  （deps: `facing/mode/shot/videoUrl/camKey`）。**不要在按鈕的 onClick 裡另外呼叫開相機**——
  會和 effect 互搶，造成回到拍攝畫面時黑畫面。放棄編輯只要 `setShot(null)`，effect 會自動重開。
- ⚠️ **串流要放 state 不能放 ref**：ref 改變不會觸發重繪，掛載 effect 就不會重跑，
  video 會一直連著已停止的舊串流（切換鏡頭失效、黑畫面的根因）。
- 快速連按切換鏡頭時，靠 effect 內的 `cancelled` 旗標丟棄過期的 `getUserMedia` 結果。
- ⚠️ **畫面上的濾鏡只是 CSS 預覽**，發佈前必須用 `bakeImage()` 把濾鏡/強度/疊加特效/文字
  畫進 canvas 才會存進圖檔（`ctx.filter` 吃的語法與 CSS filter 相同，可直接沿用濾鏡設定）。
  少了這步，上傳的會是沒套效果的原圖。
- ⚠️ **相機不負責發佈**：檢視畫面按「下一步 →」只是 `push('newPost', { photo })`，
  真正的上傳與發佈都在 `NewPost.jsx` 的 `publish()`（IG 式流程：拍完不會馬上公開，
  使用者要先在發文頁寫說明、標節氣地點、決定是否上架市集）。
  `NewPost` 收到 `photo` prop 時會隱藏選圖選項並顯示「返回重拍」。
- ⚠️ **發佈一定要 `api.uploadImage()` 取得 imageId 再帶進 `createPost`**——
  否則貼文只會顯示 📷 emoji 佔位圖（相機比圖片上傳系統早做，曾漏接這條）。
- 測試技巧：瀏覽器沒有實體鏡頭時，可覆寫 `navigator.mediaDevices.getUserMedia`
  回傳 `canvas.captureStream()` 的假串流，就能自動化驗證整個生命週期；
  再把上傳後的圖畫回 canvas 取像素，即可驗證濾鏡是否真的烘進去。

## 3. 我想改「顏色 / 字體 / 間距 / 深色模式」

- **全站配色/字體** → `src/styles.css` 最上方的 CSS 變數（token）。
  淺色在 `:root`，深色在 `[data-theme="dark"]`；改 token 全站一起換裝，**不要逐頁寫死顏色**。
- **想改某個元件的樣式** → 在 `src/styles.css` 搜該元件的 class 名。class 詞彙表見 `docs/樣式與RWD.md`。
- **RWD 三斷點**：≤559 手機 / 560–899 平板 / ≥900 桌機（網站式）。改斷點行為找對應 `@media`。
- ⚠️ **改版面前務必讀 `CLAUDE.md` 的「慣例與雷區」**（flex column 高度、月曆格、桌機 device overflow、
  `.coverbig` inline 寬度…都是踩過的坑）。

## 4. 我想「新增一個畫面」

1. 在 `src/screens/` 新建 `MyScreen.jsx`（export default 一個 React 元件）。
2. 到 `src/screens/registry.jsx` 的 `SCREENS{}` 註冊一個 key → 你的元件。
3. 想給它獨立網址 → 到 `src/store/nav.jsx` 的 `SCREEN_PATH` 加 `key: '/mypath'`（`:param` 用 props 帶入）。
4. 從別的畫面用 `push('key', props)` 進入。
> 導航方法都在 `nav.jsx`：`setTab(i)` / `push(screen, props)` / `pop()` / `popAll()`。

## 5. 我想改「後端行為 / API」

- **所有 API 路由都在 `server/index.js`**（一個檔）。想改某端點的邏輯，搜路由字串（如 `/api/works/:id`）。
- **端點總表**：`docs/API-總表.md`（依類別＋權限整理，共 40+ 支）。
- **資料庫存取**一律走 `server/db.js` 的 `db.get / db.all / db.run`（**全 async，記得 await**）。
- ⚠️ SQL **只用 `?` 佔位、時間存 ISO 字串**；**別用** `NOW()`/`SERIAL`/`AUTOINCREMENT`/boolean/timestamp 型別
  （會破壞 pg/sqlite 可移植性）。`COUNT(*) AS c` 在 pg 回字串 → 取值用 `Number(row.c)`。
- **前端呼叫 API** → 都集中在 `src/api.js`（帶 cookie + CSRF header）。新增端點記得在這裡加一個方法。

## 6. 我想改「資料庫結構（schema）」

1. 改 `server/schema.sql`（pg/sqlite 通用 DDL）。
2. 若種子要塞新資料 → 改 `server/seed.js`。
3. **本機**：刪 `server/data/auth.db*` → `npm run seed`（不砍舊檔不會補欄位）。
4. **正式 Cloud SQL**：每次部署是全新 schema，照 `docs/部署-CloudRun-PostgreSQL.md` 走。
> 表清單：`users/sessions/tokens/audit_log/orders/posts/comments/post_likes/works/follows/notifications/ref_items`。

## 7. 我想改「農民曆／命理算法」（宜忌、干支、沖煞…）

- 全部確定性演算在 `src/data/almanac.js`。想改某日的計算 → 找 `dayFor()` / `monthCells()` / `yearOverview`。
- ⚠️ **改前先讀 `CLAUDE.md` 對應雷區**：月柱用五虎遁公式、沖煞歲數是**虛歲**（不是 `||12`）。改錯會得錯誤干支/歲數。
- 可用 `node --input-type=module` 直接驗算，不用開整個 App。
- ⚠️ 這是**示範演算**（規則正確但非權威曆算）；正式版要接 lunar-javascript 或通書核對，年神方位逐年變動別沿用。

## 8. 我想改「認證 / 權限 / 安全」

- 認證邏輯、session、CSRF、速率限制、RBAC 都在 `server/index.js` + `server/db.js`；設計說明見 `docs/後端-認證.md`。
- **角色階層**：`user < creator < moderator < admin`；`requireRole(min)` 用 `roleRank` 比大小。
  moderator+ 可改內容、admin 可改角色（**admin 不能改自己角色**，防自鎖）。
- 改角色實務 → 管理後台（`Admin.jsx`）。

## 8.5 我想改「寄出去的信」（驗證信／重設密碼／訂單確認）

- **信件文案** → `server/mailer.js` 的 `TEMPLATES`（`verify`/`reset`/`order` 各有 heading/body/cta/note）。
- **信件外觀** → 同檔 `render()` 的 HTML（用 table + inline style，這是 Email 的必要寫法，別改成一般 CSS）。
- **換寄信供應商** → 只改環境變數（`RESEND_API_KEY` / `SENDGRID_API_KEY` / `BREVO_API_KEY` / `MAILGUN_API_KEY`），**不用改碼**。
- **新增一種信** → `TEMPLATES` 加一個 kind，呼叫時 `sendMail({ ..., kind:'你的kind' })`。
- **測試** → `npm run mail:test -- you@example.com`；或管理後台「系統狀態」分頁按「寄一封測試信」。
- ⚠️ **雷區**：`sendMail()` 是**同步回傳**（背景送信），呼叫端不要 `await` 期待送達結果；要等結果請用回傳的 `delivery` promise。
  寄信失敗**故意不拋錯**（不讓註冊/下單失敗），所以問題只會出現在 log，搜 `[mail]`。
- 設定教學（申請金鑰、驗證網域、上 Secret Manager）→ [docs/寄信-Email設定.md](寄信-Email設定.md)

## 8.6 我想改「AI 時光顧問」（回答範圍、語氣、模型）

- **AI 能回答什麼／怎麼婉拒** → `server/index.js` 的 `AI_SYSTEM`（服務範圍與規則）與 `AI_REFUSAL`（婉拒台詞）。
- **擋越獄／濫用的規則** → 同檔 `AI_ABUSE_RE`（輸入預檢）與 `looksLikeCode()`（輸出守門）。
  ⚠️ **修改 `AI_ABUSE_RE` 要很小心誤傷**：「今天適合寫程式嗎？」是正常的擇日提問，
  所以刻意**不擋**「寫程式」這類關鍵字，只擋程式碼區塊與明確的越獄話術。
  改完務必用正常提問複驗，別讓真實使用者被擋在門外。
- **換模型／調成本** → 環境變數 `OPENAI_MODEL`（預設 `gpt-5.4-nano`），不必改碼。價格表見 `docs/操作手冊.md`。
- **回覆長度／創意度** → 同檔 `max_tokens`（500）與 `temperature`（0.8）。
- **未設金鑰時的示範回覆** → `src/data/mock.js` 的 `aiReply`（後端回 `{fallback:true}` 時前端使用）。
- 被攔截的請求會寫 `ai_offtopic` / `ai_offtopic_output` 稽核記錄，可在管理後台查。

## 9. 我想改「部署 / 網域 / 環境變數 / 金鑰」

- **重新部署到 Cloud Run** → 照 `docs/操作手冊.md` 或 `docs/部署-CloudRun-PostgreSQL.md`（一鍵腳本 `deploy/deploy.sh`）。
- **API 金鑰 / DB 密碼** → 走 **Secret Manager**，**絕不寫進前端或 commit**。
- **金流串接** → `docs/金流-付款串接.md`；後端 scaffold 在 `server/index.js` 的 `/api/payments/*`。
- **DB 選擇**：設了 `DATABASE_URL` / `INSTANCE_CONNECTION_NAME` / `DB_HOST` → PostgreSQL；否則本機 SQLite。
  `GET /api/health` 會回目前驅動。

## 10. 改完之後要做什麼（驗證清單）

1. `npm run build` — 確認沒有 import / 語法錯誤。
2. 若改了內容/schema → `npm run seed`（本機改欄位先砍 `auth.db*`）。
3. 同時跑 `npm run dev`（前端 5173）＋ `npm run dev:server`（後端 8080），實際開畫面看。
4. 改了算法 → 用 `node` 直接驗算。
5. 改動了架構 → **回頭更新 `CLAUDE.md` 與這份 `docs/修改指南.md`**。
