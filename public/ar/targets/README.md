# AR 掃描目標

`src/data/arCards.js` 的每張官方卡片指向這個資料夾裡的**兩個**檔案：

| 欄位 | 檔案 | 用途 |
| --- | --- | --- |
| `mindTarget` | `2027-xiaohan.mind` | **MindAR 的特徵點資料庫**，追蹤真正吃的就是這個 |
| `target` | `2027-xiaohan.png` | 卡面圖，給 `/ar/card/:slug`（無相機的降級頁）當底圖、熱區校對用 |

> **2026-08-10 起 `/AR` 走 MindAR 的官方 three.js 整合**（`MindARThree`）。
> 先前那套自研的「四角偵測＋dHash 比對」已退役，這份文件底下所有跟
> **收邊**、**多視角簽名**、**localStorage 簽名快取**有關的舊規範**都不再適用**。

---

## 換一張新卡面要做什麼

```bash
npm run card:mind -- 你的設計稿.png
```

它把設計稿編譯成 `.mind`（檔名從 `arCards.js` 的 `mindTarget` 讀，不必手打），
並把同一張圖縮到短邊 900px 存成 `target` 那個 png。

**三個東西必須是同一版**，否則會歪：

1. `mindTarget`（`.mind`）
2. `target`（png 底圖）
3. `arCards.js` 的 `hotspots` 座標（相對於**卡面圖的比例**）

⚠️ 實測拿「收邊版」的 `.mind` 去掃「未收邊原稿」，投影出的卡片外框比原稿
**大 10.5%**——追蹤成功、3D 也出得來，只是所有熱區與角色的落點整體偏掉。
症狀是「東西有出現但位置不對」，不會有任何錯誤訊息。

## ★ 收邊已經不是必要條件

舊規範是「一定要加白留白邊＋深色實框」。那是為了**自研的四角偵測**——它找的是
紙與桌面的邊界，白紙放在淺色桌面上根本沒有邊界可找。

MindAR 是**特徵點比對，完全不偵測卡片邊界**。實測（1280×960、卡片佔畫面 55%）：

| | 命中 |
| --- | --- |
| 收邊版 | 12/12 |
| 未收邊原稿 | 12/12 |

所以**印什麼版就用什麼版編 `.mind`**，不必為了 AR 去改美術稿。
`npm run card:frame` / `card:install` 仍保留，但只在需要為舊路線產生收邊稿時才用。

## ⚠️ 這個資料夾少了 `.mind` 時，`/AR` 完全掃不到任何東西

不是「效果比較差」，是**完全沒有反應**：MindAR 沒有目標可比對，相機、
掃描線、取景框全部正常運作，只是永遠不會命中、3D 也永遠不會出現。
**症狀與「沒對準／光線不夠／角度太斜」一模一樣**，很容易讓人一直換角度重試。
`/AR` 會顯示橫幅講明原因，但你自己要先知道這件事。

## ⚠️ 正式站掃不到、本機卻正常？先查 CSP

MindAR 的比對跑在 **Web Worker** 裡。Vite dev server 不送 CSP 標頭，所以
`npm run dev` 一切正常、**一部署就掃不到**，而且失效完全靜默。

```bash
npm run check:live      # 打正式站，六項全 ✓ 才算過
```

驗 AR 一律用 `npm run build && npm run start`，或部署後跑 `check:live`。

## ⚠️ 換稿之後

瀏覽器會快取這兩個檔案。換稿時建議檔名加版號（`2027-xiaohan-v2.mind` /
`-v2.png`）並同步改 `arCards.js` 的 `mindTarget` 與 `target`。

## 設計稿規格

- 拉正後的**正面平整圖**（不是拍照，直接匯出設計稿）
- 匯出時儘量給高解析度；`card:mind` 會自行縮出網頁用的那一份
- 只吃 **PNG**（PNG 用 node 內建的 zlib 就能解，JPEG 要整套解碼器，
  不值得為此引入相依）。請勿勾「交錯（interlaced）」
- 卡面要有**足夠的紋理與不對稱的元素**。大面積純色、接近旋轉對稱的版面
  特徵點少，比對會不穩——這一條在 MindAR 下仍然成立
